# 大文件对比性能优化设计文档

## 概述

优化文件对比功能在处理大文件（5 万字以上）时的性能问题，确保小文件秒级响应、大文件不崩溃。

## 问题分析

### 当前瓶颈

| 瓶颈 | 严重程度 | 影响范围 |
|------|---------|---------|
| LCS DP 数组 O(m×n) 空间 | **致命** | >2 万字必崩溃 |
| `detectSimilarSegments` O(m×n×L) | **严重** | >1 万字明显卡顿 |
| 主线程阻塞 | **严重** | 任何规模都无 UI 响应 |
| 循环内重复 `preprocessText` | **高** | 每个字符位置都浪费 |

### 预期性能目标

| 文件大小 | 目标响应时间 | 当前状态 |
|---------|------------|---------|
| < 2 万字 | < 1 秒 | 卡顿/崩溃 |
| 2-10 万字 | < 3 秒 | 不可用 |
| 10-50 万字 | < 15 秒 | 不可用 |
| > 50 万字 | 拒绝处理 | 不可用 |

## 架构设计

### 整体架构

```
FileCompare.vue (主组件)
  │
  ├── 小文件 (<2万字): LCS 滚动数组（主线程）
  │
  ├── 中文件 (2-10万字): Rabin-Karp 滚动哈希（Web Worker）
  │
  └── 大文件 (>10万字): 分词 + 分块匹配（Web Worker）
```

## 算法选型

### 三层算法策略

#### 第 1 层：小文件（< 2 万字）— LCS 滚动数组

- 空间优化：DP 数组改用滚动数组，O(m×n) → O(min(m,n))
- 预处理优化：一次性预处理，不在循环内重复调用
- 执行位置：主线程

#### 第 2 层：中等文件（2-10 万字）— Rabin-Karp 滚动哈希

- 使用双哈希减少冲突
- 哈希窗口大小 = `settings.minDuplicateWords`
- 执行位置：Web Worker

#### 第 3 层：大文件（10-50 万字）— 分词 + 分块

- 按段落/句子切分为块
- 块级匹配后再精细对比
- 执行位置：Web Worker

### 算法选择决策

```
if (max(text1.length, text2.length) < 20,000):
  → LCS 滚动数组（主线程）
else if (大小 < 100,000):
  → Rabin-Karp 双哈希（Web Worker）
else if (大小 < 500,000):
  → 分词 + 分块匹配（Web Worker）
else:
  → 拒绝，提示"文件过大"
```

## Web Worker 设计

### 通信协议

**主线程 → Worker：**

| 类型 | 载荷 | 说明 |
|------|------|------|
| `START` | `text1`, `text2`, `settings`, `strategy` | 启动对比 |
| `CANCEL` | — | 取消计算 |

**Worker → 主线程：**

| 类型 | 载荷 | 说明 |
|------|------|------|
| `PROGRESS` | `progress` (0-1), `message` | 进度更新 |
| `DONE` | `segments: SimilarSegment[]`, `elapsed` | 计算完成 |
| `ERROR` | `message`, `stack` | 计算出错 |

### Worker 创建

- 使用 Vite `worker?worker` 语法
- 按需创建，用完即销毁
- 不保留常驻 Worker 实例

### 超时与取消

- 超时时间：60 秒
- 用户可随时点击取消
- 取消后调用 `worker.terminate()`

## 数据流

```
handleCompare()
  → 校验文件已上传
  → 解析文件内容
  → 检查文本有效性
  → 选择算法策略
  → 执行计算（主线程或 Worker）
  → 更新结果列表
  → 保存历史记录
```

## UI 变更

### FileCompare.vue 新增元素

1. **进度条容器**（仅 Worker 模式下显示）
   - 进度条（百分比填充）
   - 进度文本（消息 + 百分比）
   - 取消按钮

2. **状态变更**
   - `isProcessing`: 是否正在计算
   - `progress`: 进度 0-1
   - `progressMessage`: 进度消息文本
   - `canCancel`: 是否可取消

### 错误提示

| 场景 | 提示内容 |
|------|---------|
| 文件过大 (>50万) | "文件过大（XX 万字），建议拆分后对比" |
| Worker 超时 | "对比超时，文件内容过大或系统繁忙" |
| Worker 启动失败 | "Worker 启动失败，使用备用算法" |
| 用户取消 | 不显示错误，静默恢复 |

## 测试要求

1. **单元测试**：
   - Rabin-Karp 算法正确性
   - 分块匹配算法正确性
   - 边界条件（空文本、单字符、完全相同）

2. **性能测试**：
   - 1 万字 < 1 秒
   - 5 万字 < 2 秒
   - 20 万字 < 8 秒
   - 50 万字 < 15 秒

3. **集成测试**：
   - Worker 通信正常
   - 取消功能有效
   - 超时处理有效
   - 降级策略有效

## 兼容性

- Web Worker 不支持的环境降级为主线程
- 小文件策略无需 Worker，保持现有行为
- 所有变更向后兼容，不影响现有功能
